| **Customer Profiles** | عدة ملفات بأسماء، وملف افتراضي. كل الأقسام المطلوبة: Problems You Solve، وKey Benefits، وUSP، وCustomer Goals، وSuccess Stories، وInclude / Exclude Keywords، والـ ICP (المجال، والحجم، والمناصب، والدول والمناطق، والميزانية، وB2B / B2C، ومعايير أخرى). لا شيء منها إجباري غير الاسم. الملف يُختار في مربع طلب Yolias AI (فيستخدمه فهم البحث، وكلمات الاستبعاد تُضاف بالكود أيضًا)، وفي الحملة، ولكل عميل. وفحص التوافق كود وليس ذكاءً اصطناعيًا. |

| **Rules & Permissions** | لكل وكيل وكل إجراء: تلقائي، أو يحتاج موافقة، أو غير مسموح. حدود الإرسال (رسائل لكل عميل، ورسائل يوميًا، وساعات بين الرسائل، ومدة منع إعادة التواصل، والإيقاف عند الرد أو حجز اجتماع). قواعد التصعيد (طلب التوقف وعدم وجود صلاحية مفعّلان دائمًا). والإرشادات. **تُطبَّق على الخادم** في كل وكيل وأتمتة، وفي بدء البحث، وفي أدوات Yolias AI نفسها، وليس بإخفاء الأزرار. |
| **Automations** | اسم، وحدث (إضافة عميل، أو تغيير مرحلة، أو حجز اجتماع، أو انتهاء اجتماع، أو تسجيل رد، أو انتهاء حملة بلا رد)، وشروط اختيارية، وحتى 5 إجراءات (تذكير، أو إشعار، أو ملاحظة، أو إيقاف المتابعات، أو نقل مرحلة)، وتشغيل وإيقاف وتعديل وحذف مع بقاء السجل، وسجل تنفيذ يحفظ النتيجة وسبب الفشل. الأمثلة الأربعة التي طلبتها جاهزة كقوالب. لا يوجد إجراء يرسل رسالة، ونفس الحدث لا يشغّل الأتمتة مرتين، وتغييرات الأتمتة لا تشغّل أتمتة أخرى. |

## 2. قاعدة البيانات

Migration واحد إضافي: `Yolias/supabase/migrations/20261111000000_acquisition_workspace.sql`.

- **جداول جديدة:** `leads`، و`lead_activities` (السجل)، و`lead_tasks` (التذكيرات)، و`meetings`، و`outreach_campaigns`، و`outreach_steps`، و`outreach_enrollments`، و`inbox_threads`، و`workspace_knowledge`، و`business_offers`، و`competitors`، و`customer_profiles`، و`workspace_ai_settings`، و`automations`، و`automation_runs`، و view `crm_leads`.
- **أعمدة جديدة:**
  - `profiles`: المصدر، ونص «أخرى»، وتاريخ الإجابة، ومشاهدة الفيديو.
  - `strategies.customer_profile_id`.
  - `outreach_messages`: العميل، والحملة، والخطوة، والاتجاه، وموعد الإرسال، وطريقة الإرسال، والرد، والتحليل.
  - `agent_pending_actions`: العميل والوكيل.
- **الحماية:**
  - RLS على كل جدول، ومعها شرط التحقق الثنائي.
  - المعرفة والقواعد والأتمتة للمالك والمسؤولين فقط.
  - قيود ضد التكرار: عميل واحد لكل شخص أو شركة، واشتراك واحد في كل حملة، ومسودة واحدة لكل خطوة، وتشغيل واحد لكل حدث، وتذكير واحد لكل موعد.
  - Triggers للسجل، ولإيقاف الحملات عند الخسارة أو الإغلاق أو طلب عدم التواصل، ولمنع ربط بيانات من مساحة عمل أخرى.
- **بيانات الإنتاج:** لا حذف ولا تعديل لأي بيانات موجودة. اتأكدت إن الملف النهائي يتطبق كاملًا على الشكل القديم للقاعدة، داخل transaction اترجعت.

**إعداد جديد:** `site_settings.yolias_welcome_video` (متوقف افتراضيًا).

## 3. التكاملات التي تعمل فعلًا

- **الذكاء الاصطناعي** (Gemini عبر مركز التكاملات): اتجرّب محليًا بمفتاحك. كتب مسودة حملة حقيقية مربوطة بالعميل والخطوة، وقرأ ردًا وصنّفه «يريد اجتماعًا». بدون مفتاح كل خطوة بترفض بوضوح، وطلبات التوقف بتتعرف بالكود.
- **الـ Worker:** تذكيرات المتابعة والرسائل المجدولة والاجتماعات بلا نتيجة.
- **روابط الفتح:** فتح الرسالة جاهزة في Gmail أو Outlook أو تطبيق البريد أو واتساب أو LinkedIn. هي نفس الآلية الحالية، ومحسوبة في حد الإيميلات الشهري زي الأول.

## 4. ما يحتاج تكاملًا خارجيًا (غير متصل، ومكتوب كده في الواجهة)

- **إرسال الرسائل تلقائيًا من البريد (Gmail / Outlook):** الإرسال يتم من حسابك، وبعدها تضغط «أرسلتها». زر «إرسال (يحتاج بريدًا متصلًا)» معطّل وفيه شرح.
- **استقبال الردود تلقائيًا:** الرد يتسجل يدويًا («سجّل ردًا وصلك»).
- **إنشاء الاجتماعات وروابطها (Google Calendar / Meet / Zoom):** الاجتماع يتسجل بالرابط اللي أنت عملته.
- **إرسال LinkedIn بـ API:** غير متاح إلا لشركاء LinkedIn.
